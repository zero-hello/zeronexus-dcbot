# ZeroNexus 第十章：故障同理心與人性化錯誤指引規範

## 1. 錯誤訊息的人性化原則
系統故障是分散式與外部服務整合難以完全避免的物理現實，但錯誤如何傳遞給使用者，直接決定了 ZeroNexus 的產品品質與溫度：
- **禁止輸出裸 Traceback**：
  ❌ 嚴禁讓使用者在 Discord 看到 `Traceback (most recent call last): File ".../main.py", line 42, in ...`，更不可洩漏環境變數中的任何 API 金鑰或內部資料庫路徑。
- **禁止 Linux Kernel 式代碼**：
  ❌ 避免輸出如 `ERROR 0x0000005F: BAD_GATEWAY` 等對一般社群成員毫无意義的機械代碼。
- **錯誤呈現黃金三要素**：
  每一則錯誤或降級訊息必須清晰交代：
  1. **發生了什麼事**（用溫和明確的自然語言說明，例如：「音樂節點連線逾時」）。
  2. **當前的系統狀態**（說明受影響範圍：「音樂功能已自動進入保護性停用，但其他管理、工具與 AI 功能完全不受影響」）。
  3. **使用者現在能做什麼**（提供清晰行動路徑：「若您是管理員，可使用 `/系統 模組 重啟 音樂` 嘗試重新連線，或稍候由背景自動重試」）。

## 2. 容錯自癒與錯誤引導原則
當主要 AI 提供者（如 Gemini）因配額耗盡（429）或逾時，由系統 AI Gateway 自動容錯移轉時：
- 由 Python 系統閘道層負責記錄與在 Discord 介面呈現切換狀態，AI 在回答內容中保持公開誠實、不刻意隱瞞系統背後的自動修復與自癒歷程。
- AI 本身絕不可在文字中手動拼湊偽造的模型切換頁尾（如 `🤖 DeepSeek V3 · ↳ Gemini ...`），而是專注於用同理心與專業態度回答使用者的問題。若因特定功能降級而影響部分回答精度，應直接在正文中以自然語言誠懇說明。
